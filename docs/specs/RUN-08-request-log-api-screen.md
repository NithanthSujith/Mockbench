# RUN-08 — Request-log API and screen

Status: approved
Phase: 4   Team: Runtime
Depends on: RUN-07, BLD-04
Size: M

## Goal
At `/p/$projectSlug/logs` a user sees recent requests to the project — filterable, live-refreshing — and can tell a mocked error from a mock-server error at a glance.

## In scope
- Handler `requests.list` with filters and cursor pagination.
- The screen (TanStack Table): time, method badge, path, case, status chip, ms, from; filter bar (status class, method, path text, "mock-server errors only"); row expand for headers/query; auto-refresh toggle (3 s poll); empty states.

## Out of scope
The writer and pruner (RUN-07); export; charts.

## Contract
Endpoint `requests.list` (API-CONTRACT §3.10). Table `request_logs` (+ `versions.label` join). UI route `/p/$projectSlug/logs`.

## Acceptance criteria
- [ ] `GET …/requests` returns newest first with `limit` (default 50, max 200), `nextCursor` over 120 rows pages 50/50/20; `limit=201` → `422`; a tampered cursor → `400 invalid_cursor`.
- [ ] Filters AND together: `status=4xx` returns only 400–499; `status=404` only 404; `method=POST`; `path=invoices` matches case-insensitively as a substring; `since=<ts>` excludes older rows; `mockError=true` returns only rows with a non-null `mockError`.
- [ ] Each item includes `versionLabel` (null when the version was deleted or the project was unpublished) and the redacted headers as stored; `ip` is present.
- [ ] Viewer can read; a non-member gets `404`; the response parses against the registry schema.
- [ ] The screen renders the prototype table; the status chip uses the 2xx/4xx/5xx classes; rows with `mockError` show a "mock server" tag and the hint text "mocked 404s are your own cases; these were generated by the server".
- [ ] Changing a filter re-queries with the corresponding parameters and resets the cursor; "Load more" appends the next page.
- [ ] Auto-refresh polls every 3 s only while the tab is visible, prepends new rows without losing scroll position, and can be paused.
- [ ] Expanding a row shows request headers (redacted values shown as `[redacted]`) and query as mono key/value pairs.
- [ ] A project with no requests shows "No requests yet. The log starts filling once this project is deployed."; one with no active version says the same plus a link to Versions.
- [ ] The retention note says entries are pruned automatically, without hard-coded numbers unless the server exposes them (see Open questions).

## Tests
Handler tests (filters, pagination, role matrix); Testing Library for table states; Playwright poll/refresh test in MSW mode.
